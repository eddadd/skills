# spec 增强预检清单

本清单用于 openspec 生成产出物**之前**逐条过验。每条适用才勾选，不适用默认通过；出现「否」必须修正后再进入 openspec 流程。本清单仅作检查，不落盘。

## A. 拆解完整性

- [ ] A1 需求已拆为「能力 / 需求 / 场景 / 边界」四层，无缺失层
- [ ] A2 已列出明确的「不做」清单（非目标、批量操作、字段展示范围等）
- [ ] A3 已识别逆向约束（`禁止` / `必须不` 形式的隐性需求）并拟成独立场景
- [ ] A4 已点名跨模块契约涉及的具体文件（路由、query、接口、常量、动态路由权限、缓存）
- [ ] A5 已显式声明每个决策点（选 A 不选 B + 一句理由）
- [ ] A6 已显式声明字段关联性（关联联动对「A→B」+ 独立对「A 不影响 B」），避免实现时误把独立字段纳入联动清空
- [ ] A7 已核对新字段取值形态与承载组件的入参类型约束（如布尔 value vs `FsSelect` 的 `String|Number|Array`），不兼容已声明采用「扩展组件」还是「改传值形态」
- [ ] A8 同名字段多来源（列表/详情/导出等）已列出来源清单 + 一致性口径（以谁为准 / 不仲裁则挂核对任务）+ 多消费点判定口径归一化（如统一 `=== true`）
- [ ] A9 已核对承载组件是否提供计划用到的能力（插槽透传、展开行、分页开关等），不透传已声明替代方案（如 `fs-table` 不透传 `expandedRowRender` → 改 `a-table`）
- [ ] A10 已核对每个接口的返回结构形态（分页对象/单对象/数组）+ 字段全集归属（列表项 vs 详情项各返回哪些字段），列表/详情字段重叠时已显式声明归属
- [ ] A11 用户粘贴契约/枚举片段时，已核对字段归属（同名标注冲突、语义与字段名不符），不照抄标注、不确定先问
- [ ] A12 未点名控件类型的筛选/表单字段默认按文本输入框，并显式列出「哪些是下拉/日期、其余文本」作为可核对清单
- [ ] A13 新建页面/详情页要素默认值已逐项确认（返回按钮/卡片结构/导出位置与入参/列表分页/展开行结构/时间列位置）

## B. 颗粒度可验证（AI 不跑偏阈值）

- [ ] B1 每条需求已拆成可独立验收的场景，无「一条需求一个大段落」的糊块
- [ ] B2 场景「当」可构造（能指出怎么触发）、「那么」可观察（能看到现象）
- [ ] B3 验收点可量化：有字段数、请求次数、枚举项数、选项数等可数指标
- [ ] B4 涉及新旧并存时，验收点有「逐项对照」类比对标准
- [ ] B5 全文无自我验收措辞（`合理即可` / `正常展示` / `妥善处理` / `美观` / `友好提示` / `不报错` / `视情况` / `尽量`）
- [ ] B6 产出物正文使用中文书写（代码/接口/类型等强制技术标识符除外，禁止英文叙述混入）

## C. 边界覆盖

- [ ] C1 空值/缺块边界已写独立场景（值 `null`/`undefined`/`''` 展示兜底，块缺失不渲染标题）
- [ ] C2 非法枚举/非法值边界已写独立场景（不报错 + 兜底）
- [ ] C3 请求失败/错误态边界已写独立场景（失败展示 + 页面其余可交互）
- [ ] C4 下拉空选项边界已写独立场景（选项为空 + 不报错）
- [ ] C5 时序边界已写独立场景（首次/切走切回/往返切换的请求挂载次数）
- [ ] C6 权限/404 边界已写独立场景（无权限路由不注册、直接访问 404）；新增 `hideInMenu` 隐藏详情路由时，已在预检阶段确认后端菜单是否返回该 name 并选定放行方式
- [ ] C7 串号/缓存边界已写独立场景（切换主体不串号、缓存行为明确）
- [ ] C8 每个模块验收标准包含 `边界：` 条目，且可量化

## D. 与 openspec 配合

- [ ] D1 本 skill 未生成/修改任何产出物（不落盘约束）
- [ ] D2 拆解结论已作为增强上下文注入，可进入 openspec 流程
- [ ] D3 每个模块验收标准独立成条目（`验收标准：` 前缀），可转测试断言，不揉进叙述段落
- [ ] D4 验收标准描述外部可观察行为（渲染/请求次数/入参内容/显隐），不依赖内部实现细节（函数名、switch 写法），可被测试 skill 消费
- [ ] D5 验收标准与 spec 场景互补：spec 约束行为，验收标准约束「如何验证」，两者同时存在
- [ ] D6 已扫描本次涉及的既有主 spec 章节头格式（`## 需求` 被解析器识别，`## 新增需求` 等变体不兼容），发现不兼容已标注修正
- [ ] D7 delta 标题格式与主 spec 既有标题逐字一致（`### 需求:<名称>` 中文格式，禁止 `### Requirement:` 英文格式）
- [ ] D8 本 skill 未做浏览器验证/端到端实测/测试用例生成——验证属测试 skill 职责，验收标准只写成可转断言的外部可观察行为即可
