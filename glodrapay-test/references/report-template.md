# 测试报告模板（tests/report/<YYYYMMDD>/测试报告.md）

按以下五段结构生成，全部中文。文件头为 `# <变更名> 测试报告`。

## 文档头（元信息列表）

```markdown
# <change-name> 测试报告

- 日期：<YYYY-MM-DD>
- 被测对象：<openspec 变更名（中文说明）>
- 测试环境：vitest 单测（jsdom | 无 @vitejs/plugin-vue）
- 依据：tasks.md 验收标准编号 + spec 场景（无 openspec 时写用户描述或"无"）
- 测试文件：`tests/unit/<业务名>-logic.test.ts`
```

## 1. 结论摘要

- 断言通过率：**通过 X / 失败 Y / 无法验证 Z**（共 N 条）
- R 级问题：**R1 a 个、R2 b 个、R3 c 个**
- 覆盖缺口：一句话概括哪些需浏览器实测/联调

如有用户纠正或被测重构（如纯函数抽取），在摘要后加 `> 说明：` 引用块注明。

## 2. 断言结果明细

表格，每行必有证据：

```markdown
| 编号 | 断言 | 结果 | 证据 |
| --- | --- | --- | --- |
| C-01 | <常量/取值类断言> | 通过 | expect(...) 表达式 |
| T-01 | <正向用例> | 通过 | expect(...) 表达式 |
| R-01 | <反向/兜底用例> | 通过 | expect(...) 表达式 |
```

编号约定：C=常量，Q=查询/转换，T=文案/展示逻辑，R=角色/权限，A=走查断言。走查可达但无法单测的断言，结果列写"走查通过"或"无法验证"，证据列写走查证据（源码位置 + grep 结果等）。

## 3. R 级问题清单

```markdown
| 级别 | 位置 | 问题 | 处置 |
| --- | --- | --- | --- |
```

无问题时写"无"。已随用户纠正解决的问题，处置列写"已随纠正解决"并简述。

## 4. 遗留事项

- 需浏览器实测/联调的运行时场景，逐条列出（含场景编号），说明需联调原因
- 记录路径/规范类决策（如报告路径变更）供后续会话继承

## 5. 变异抽查记录

- 未执行时：写"未执行"并说明正反双向已覆盖的关键判定
- 执行时：列出被变异的分支、变异后测试是否失败（失败=测试有效）
