# 边界覆盖引导与代码走查清单

防止 AI 只测快乐路径的两张清单：**业务行为层边界用例清单**、**代码质量层走查清单**。

---

## 一、业务行为层：七类强制边界用例

每类边界都要独立成用例（不是正常路径里的一句话），适用即测，不适用说明理由：

| # | 类别 | 用例构造 | 判定标准 |
| --- | --- | --- | --- |
| 1 | 空值 | 列表无数据 / 字段 null / undefined / '' | 展示兜底（`--` / 空态图），不抛错 |
| 2 | 非法值 | 非法枚举 / 超长输入 / 特殊字符 | 不报错，走兜底分支或被拦截 |
| 3 | 失败态 | 接口 500 / 超时 / 返回结构错 | 失败提示出现，页面其余可交互 |
| 4 | 空选项 | 下拉数据为空数组 | 下拉可打开且无选项，不抛错 |
| 5 | 时序 | 首次进入 / 切走再切回 / 往返切换 | 请求次数符合 spec（如恰 1 次，不重复请求） |
| 6 | 权限 | 无权限角色访问 / 无权限码账号 | 路由不注册或按钮不渲染，直接访问 URL 不崩 |
| 7 | 串号 | 快速切换主体（Tab / 行 / 筛选） | 数据不串、旧请求不覆盖新结果 |

### 1.1 正反对照构造法

同一页面同时构造正反数据，一次验证两条断言：

- 例：PENDING 行有「审核」按钮 + PASS 行没有 → 同时验证显隐规则的两个方向；
- 例：有 `user:export` 权限账号看到导出按钮 + 无权限账号看不到。

### 1.2 时序/防重的实测手法

- 防重复点击：点击后立刻再点，network 面板确认请求总数仍为 1；
- 切换串号：切 A → 立刻切 B，确认最终渲染数据是 B 的响应（network 时间序 + DOM 内容双向对照）。

## 二、代码质量层：五类走查清单

对被测模块源码逐项过，产出 R 级问题清单（`文件:行号 / 问题 / 级别 / 建议`）：

### 2.1 响应性（R 高发区）

- [ ] 异步回调 / 校验规则里的 `t('xx')` 是否包了箭头函数（`message: () => t('xx')`）——不包则语言切换后不更新；
- [ ] `setTimeout` / Promise 回调里是否直接改非响应式变量；
- [ ] 组件卸载后定时器 / 监听是否清理。

### 2.2 边界与兜底

- [ ] 每个接口调用的 catch 是否有用户可感知的兜底（提示 / 空态），而非静默吞掉或抛错；
- [ ] 可选链 `?.` 之后的取值是否还有下一步空值风险；
- [ ] 数组方法（map / filter）的入参是否可能为 null/undefined。

### 2.3 权限与显隐

- [ ] 按钮 / 操作列显隐是否绑权限码（`v-auth`），与 spec 的权限场景一致；
- [ ] 无权限时是「不渲染」还是「渲染后禁用」——与 spec 约束核对（多数 spec 要求不渲染）。

### 2.4 竞态与时序

- [ ] 提交 / 导出等动作是否有 loading 防重；
- [ ] 切换主体后旧请求返回是否会覆盖新数据（请求序号 / abort 机制）；
- [ ] 轮询 / 定时刷新在页面隐藏时是否暂停。

### 2.5 规范符合性（按项目 AGENTS.md）

- [ ] 箭头函数（API 层除外）；
- [ ] 显式类型标注、禁 `any`；
- [ ] 无魔法值（枚举走具名常量对象）；
- [ ] 注释规范（`@function` / `@constant` / `<!-- S 区块 -->`）；
- [ ] async 配套 try/catch/finally。

## 三、R 级问题分级

| 级别 | 定义 | 处置 |
| --- | --- | --- |
| R1 | 功能错误：行为与 spec/验收标准直接冲突、崩溃、数据串号 | 当场修复 + 回归 |
| R2 | 质量缺陷：响应性丢失、边界无兜底、竞态隐患 | 能修则修，修完回归；不能修列遗留 |
| R3 | 规范问题：违反项目编码规范、注释缺失 | 列清单，批量修复需用户确认 |
