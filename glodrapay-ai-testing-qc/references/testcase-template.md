# 模板：测试用例登记表 + 测试报告

两个模板直接复制使用，占位符 `<...>` 替换为实际内容。

---

## 一、测试用例登记表（第一步产出）

```markdown
# <变更名> 测试用例清单

来源：openspec/changes/<name>/tasks.md（验收标准 N 条）+ specs/<capability>/spec.md（场景 N 个）

| 编号 | 类型 | 断言（保持中文原文） | 来源 | 验证方式 | 结果 |
| --- | --- | --- | --- | --- | --- |
| A-01 | 请求 | 点击导出后 exportUserServer 恰调用 1 次 | T3.2 / S5 | network | 待测 |
| A-02 | 显隐 | 无 user:export 权限时导出按钮不渲染 | T4.1 / S2 | DOM | 待测 |
| A-03 | 反向 | 导出中重复点击不重复发起请求 | T3.3 / S7 | network | 待测 |

覆盖对照：spec 场景 N 个 → 断言 M 条（缺口：无 / Sx 无对应断言）
```

规则：反向用例必须有（占比 ≥ 40%）；「验证方式」只能是 network / DOM / 走查 / 单测四种之一。

## 二、测试报告（第四步产出）

> 存放路径固定为**当前项目根目录下 `tests/report/<YYYYMMDD>/`**（如 `tests/report/20260921/测试报告.md`），目录不存在则新建；同一测试对象同日多轮测试可加日期后缀区分。

```markdown
# <变更名> 测试报告

- 日期：<YYYY-MM-DD>
- 被测对象：<模块 / change 名>
- 测试环境：<dev 地址 / mock 说明>
- 依据：tasks.md 验收标准 N 条、spec 场景 M 个

## 1. 结论摘要

- 断言通过率：通过 X / 失败 Y / 无法验证 Z（共 N 条）
- R 级问题：R1 a 个（已修复 a1）、R2 b 个、R3 c 个
- 覆盖缺口：<哪些场景没测到、原因>

## 2. 断言结果明细

| 编号 | 断言 | 结果 | 证据 |
| --- | --- | --- | --- |
| A-01 | ... | 通过 | network: exportUserServer ×1，入参无 page |
| A-02 | ... | 失败 | DOM: 按钮仍渲染（见 R1-1） |
| A-05 | ... | 无法验证 | 需真实联调（后端接口未就绪） |

## 3. R 级问题清单

| 编号 | 位置 | 问题 | 级别 | 处置 |
| --- | --- | --- | --- | --- |
| R1-1 | src/views/.../index.vue:88 | 校验 message 未包箭头函数，语言切换不更新 | R1 | 已修复并回归 A-02 |

## 4. 遗留事项

- <无法验证的链路及原因>
- <建议补充的测试数据 / 联调项>

## 5. 变异抽查记录（可选）

- 变异点：<文件:行号，改了什么> → 测试结果：<抓住 / 未抓住> → 已还原（rg 确认 0 残留）
```

## 三、单测文件骨架（可选层）

```ts
// <source>.test.ts —— 对应 tasks.md 验收标准 T<x.y>
import { describe, expect, it } from 'vitest'
import <fn> from '<source-path>'

describe('<fn>：<一句话说明被测行为>', () => {
  it('正向：<断言原文（中文）>', () => {
    expect(<fn>(<input>)).<matcher>
  })
  it('反向：<边界输入时不应崩溃/应走兜底>', () => {
    expect(() => <fn>(<badInput>)).not.toThrow()
  })
})
```

规则：只转「纯函数 / 状态逻辑」类断言；UI 断言不强行转；生成后 `pnpm test` 全绿才算交付。
